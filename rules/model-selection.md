# Choose effort for the task

Use the project's configured model unless the user or team has set a different policy. Before a long task, identify whether it is execution against a settled brief or a design decision with unresolved tradeoffs. Recommend a lower-cost model only when the work is bounded and the expected quality remains sufficient. Recommend a more capable model when flow strategy, competing constraints, or uncertain debugging warrants it.

Treat model prices, context billing, and model availability as current product facts to verify, not permanent rules in this repository. Do not interrupt a task just to discuss model selection unless the user requested cost optimization or a change would materially affect the work.
