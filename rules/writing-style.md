# Design writing style

Use the language requested by the designer and keep interface copy in the product's target language. Write concisely without dropping the decision, its reason, remaining uncertainty, or the next action.

Use one main idea per paragraph. Tables help compare screen variants or map current copy to proposed copy, but do not turn every answer into a table. Refer to exact screen or node IDs only when they help the reader find the work; keep project-specific IDs in private project files.

For handoff, distinguish what is approved from what is still exploratory. Put implementation values where engineers can find them and keep design-process history in a separate decision log.
